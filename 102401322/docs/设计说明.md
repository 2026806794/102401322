# 项目设计与技术栈说明

> 对应博客章节 3.1「项目设计与技术栈」与 3.2「爬虫与数据处理」

## 一、任务拆解

从阅读题目到完成作业，整个任务被拆成 8 个环节：

| # | 环节 | 完成方式 | 产出 |
| - | ---- | -------- | ---- |
| 1 | 接口调研 | 用 requests 手工探测 B 站搜索/详情/弹幕接口，确认鉴权方式 | 接口可用性结论：搜索需要 wbi 签名 |
| 2 | 爬虫实现 | 自研 wbi 签名 + 三级弹幕降级通道 + 缓存断点续爬 | `src/crawler/` |
| 3 | 噪声治理 | 阅读弹幕样本，归纳三类噪声（词表/正则/停用词） | `src/processing/noise_lexicon.py` |
| 4 | 清洗与分词 | 规范化 + 刷屏去重 + jieba 领域词典分词 | `src/processing/` |
| 5 | 统计口径设计 | 定义 5 类领域词典（案例/领域/态度/成本/风险） | `src/analysis/lexicon.py` |
| 6 | 统计与导出 | Aho-Corasick 加速多标签匹配 + pandas 导出 13 表 | `src/analysis/` |
| 7 | 可视化 | matplotlib 词云/统计图 + 自建 ECharts 大屏 | `src/visualization/` |
| 8 | 质量保障 | 155 个单元测试 + flake8/pylint 检查 + cProfile 剖析 | `tests/`、`scripts/` |

## 二、分层架构

```
                    main.py (CLI)
                         │
                    pipeline.py (编排)
                         │
   ┌─────────────┬───────┴────────┬──────────────┐
   ▼             ▼                ▼              ▼
crawler  →   processing   →   analysis   →   visualization
 (取数)        (净化)          (统计)          (呈现)
   │             │                │              │
   └─────────────┴────────────────┴──────────────┘
              统一通过「文件契约」通信
        data/raw/*.json → data/processed/*.json(l) → output/*
```

**核心设计原则：阶段之间只通过落盘文件通信，不直接传对象。**

这样做的收益：

* 任一阶段可以单独重跑（改统计口径不必重爬）；
* 每个阶段都能脱离前后依赖单独测试；
* 数据可追溯：原始响应、清洗结果、统计结果各自留档。

## 三、关键类与函数

### 3.1 爬虫层

| 类 / 函数 | 职责 | 关键设计 |
| -------- | ---- | -------- |
| `wbi.sign_params()` | 生成 `w_rid`/`wts` 签名 | 纯函数、可注入时间戳，因此能写回归测试 |
| `BilibiliClient._request()` | 统一 HTTP 出入口 | 随机间隔 + 指数退避 + 412 长冷却 + 可覆盖重试次数 |
| `BilibiliClient.search_videos()` | 关键词搜索 | 综合排序 `order=totalrank`，过滤非 BV 结果 |
| `parse_danmaku_xml()` | 解析 deflate 压缩 XML | 解压失败自动回退明文，单条坏数据跳过而非中断 |
| `parse_danmaku_proto()` | 手写 protobuf varint 解析 | 免去 protobuf 运行时依赖，字段未知时安全跳过 |
| `DanmakuCrawler._fetch_danmaku_by_cid()` | 三级降级抓弹幕 | 见下节"三级通道" |
| `DanmakuCrawler.collect_videos()` | 视频清单管理 | 合并式增量补齐，空页重试，按关键词分档落盘 |

**三级弹幕降级通道**（本项目最有价值的爬虫设计）：

| 优先级 | 通道 | 特点 |
| ----- | ---- | ---- |
| 1 | `comment.bilibili.com/{cid}.xml` | 一次请求拿全量；限流策略最宽松 |
| 2 | `api.bilibili.com/x/v1/dm/list.so` | 结构相同但限流更严 |
| 3 | `api.bilibili.com/x/v2/dm/web/seg.so` | protobuf 分段（6 分钟/段），属另一限流桶 |

每个通道都带**熔断器**：连续失败 3 次即判定通道级限流并永久跳过该通道。
没有熔断时，每个视频都要为注定失败的请求付出约 2 分钟指数退避代价——
这是实测出来的优化，不是臆测。

### 3.2 处理层

| 类 / 函数 | 职责 | 关键设计 |
| -------- | ---- | -------- |
| `DanmakuCleaner.clean_record()` | 单条清洗与噪声判定 | 三类噪声分档计数，样本留档便于报告中举例 |
| `DanmakuCleaner.clean_batch()` | 批量清洗 | 去重键为「视频+用户+文本」：同一用户刷屏才算噪声，不同用户说同样的话是真实共鸣 |
| `Segmenter.segment()` | 分词 + 停用词过滤 | 带结果缓存（剖析发现分词占 74% 的耗时，是最大瓶颈） |

### 3.3 分析层

| 类 / 函数 | 职责 | 关键设计 |
| -------- | ---- | -------- |
| `AhoCorasick` | 433 个领域模式的并行匹配 | Trie + BFS 失败指针 + 输出合并，复杂度 O(文本长度+命中数) |
| `DanmakuAnalyzer.analyze()` | 一次遍历产出全部统计 | 一条弹幕只分词一次，分词结果同时喂给整体词频与各领域词频 |
| `_progress_bucket()` | 弹幕出现时间归一化到视频进度 | 用各视频时长归一，避免长视频天然占优 |
| `ExcelExporter.export()` | 13 个工作表导出 | pandas 组织数据 + openpyxl 套用表头样式与冻结窗格 |
| `TrendAnalyzer` | 附加题：媒体趋势与外推 | 剔除不完整月份 + 连续窗口截取，避免 RSS 近期偏置造成假趋势 |

### 3.4 可视化层

| 模块 | 职责 |
| ---- | ---- |
| `theme.py` | 统一配色与中文字体注册（`addfont` + 字体族名，否则中文变方块） |
| `wordcloud_chart.py` | 4 张词云：总体 / 案例 / 风险担忧 / 分领域组合 |
| `charts.py` | 6 张统计图：领域分布、Top8 案例、态度环形、成本风险、进度分布、关键词对比 |
| `dashboard.py` | 可视化大屏：手写 ECharts 配置 + CSS Grid，离线可用 |
| `trend_report.py` | 附加题报告：视频发布趋势、媒体 vs 用户话题对比、来源分布 |

## 四、关键算法说明

### 4.1 wbi 签名

B 站 web 接口要求 `w_rid` 参数。算法：取 `img_key` 与 `sub_key` 拼接成 64 位串，
按前端硬编码的置换表重排后取前 32 位作为 `mixin_key`；请求参数加时间戳 `wts`，
按 key 升序拼接为 query，`md5(query + mixin_key)` 即签名。密钥每日轮换，
失效时从 `nav` 接口重新获取。

### 4.2 多标签领域归类

一条弹幕可能同时属于多个领域（"用显卡跑本地大模型写代码"同时命中硬件算力与编程开发），
因此采用**多标签计数**而非单选分类。433 个别名通过 Aho-Corasick 自动机一次扫描命中，
避免逐别名 `in` 判断的 O(N×M) 开销。

### 4.3 噪声三层治理

| 层级 | 手段 | 例子 |
| ---- | ---- | ---- |
| 整条丢弃 | 精确词表 `NOISE_EXACT` | `666`、`前排`、`哈哈哈哈`、`求资料` |
| 整条丢弃 | 正则规则 `NOISE_PATTERNS` | 纯数字、纯符号、`@某人`、链接、纯 emoji、单字刷屏 |
| 分词过滤 | 停用词 `DANMAKU_STOPWORDS` | 虚词 + 灌水词 + 教程类视频的"求资源"高频词 |

此外还做了文本规范化（去零宽字符、压缩叠字、剥离内联的 @/链接/表情），
以及"同用户同视频重复刷屏"去重。

### 4.4 进度归一化

弹幕自带出现时间（秒），但不同视频时长差异极大（1 分钟到 15 小时）。
因此统计"弹幕随视频进度的分布"时按各视频时长归一化到 10 个分桶，
否则长视频会天然占据绝对优势。

## 五、技术栈清单

* **语言**：Python 3.13
* **爬虫**：requests（+ 自研 wbi 签名、deflate 解压、protobuf varint 解析）
* **中文处理**：jieba（自定义领域词典 145 词）
* **算法**：自研 Aho-Corasick 自动机
* **数据**：pandas、numpy、openpyxl
* **可视化**：matplotlib、wordcloud、Apache ECharts（本地静态资源，离线可用）
* **测试**：pytest、pytest-cov
* **性能**：cProfile、pstats、snakeviz（可选）
* **开发环境**：Visual Studio Code
